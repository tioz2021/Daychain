# Техническое задание: трекер привычек «habits» (нативный клиент)

| | |
|---|---|
| Версия документа | 2.0 |
| Дата | 2026-10-30 |
| Статус | реализовано: нативный клиент на Raven, веб-версия удалена |
| Платформа | Linux, X11 (Wayland через XWayland), Vulkan |
| Лицензия | MIT (Raven — Apache 2.0, собирается из исходников) |

## 1. Цель и рамки

Однооконное настольное приложение для личных привычек: расписания, отметки
«выполнено / пропущено», заметки к дню, серии, heatmap и счётчик отказа от
вредных привычек. Всё состояние хранится в одном JSONL-файле рядом с бинарником.

Вне рамок: сеть, аккаунты, синхронизация, напоминания, мобильные платформы,
веб-интерфейс, несколько пользователей.

## 2. Архитектура

```
src/desktop/  окно на Raven: экраны, диалоги, кастомная отрисовка heatmap
src/core/     модель, расписание, серии, проценты, хранилище JSONL
src/infra/    UTF-8, гражданские даты, JSON, файловые операции
```

Ядро не знает про Raven: время и данные передаются параметрами, поэтому
тестируется без GUI. Окно — единственное место, где вызывается Raven API.

Зависимости: Raven 0.1.x (C11 + Vulkan, Apache 2.0), X11, libc, POSIX.
Raven не вендорится: `tools/get_raven.sh` клонирует и собирает его в `build/`.

## 3. Модель данных

Файл `data/habits.jsonl`, UTF-8, одна JSON-запись на строку, `schema_version = 2`.

| Тип | Назначение | Ключевые поля |
|---|---|---|
| `meta` | первая строка | `schema_version`, `created_at` |
| `habit` | привычка | `id`, `name`, `color`, `icon`, `schedule`, `start_date`, `archived_at`, `sort_order` |
| `entry` | отметка дня | `habit_id`, `date`, `status` (`done`/`skipped`), `note`, `updated_at` |
| `quit` | счётчик воздержания | `started_at`, `best_seconds`, `attempts`, `archived_at` |

Расписание: `daily`; `weekdays` с набором ISO-дней (1 = пн); `weekly_count`
с квотой 1..7 на ISO-неделю. Запись — снапшот: файл перезаписывается целиком,
атомарно (temp + rename), предыдущая версия остаётся в `.bak`.

## 4. Правила вычислений

- **Плановый день**: `daily` — любой день после `start_date`; `weekdays` —
  совпадение дня недели; `weekly_count` — любой день, квота контролируется неделей.
- **Квота недели**: `max(0, times − пропуски_за_неделю)`.
- **Серия (дни)**: идём назад по плановым дням; `done` +1, `skipped` нейтрален,
  пропуск отметки обрывает. Неотмеченный сегодняшний день серию не обрывает.
- **Серия (недели)**: недели назад, закрытая неделя +1; текущая незакрытая
  не обрывает и не добавляет.
- **Процент**: `done / (плановые − пропуски)`; для `weekly_count` — среднее
  недельных кредитов `min(1, done / квота)`, текущая неделя не учитывается.
- **Heatmap**: 12 ISO-недель, состояния `done`, `skipped`, `miss`, `off`, `future`.

## 5. Экраны

| Экран | Содержимое |
|---|---|
| Сегодня | заголовок с датой и стрелками, карточки привычек: иконка, название, серия, прогресс недели; кнопки Note, Done, Skip |
| Привычки | список с расписанием; создание и правка в диалоге (название, описание, цвет, иконка, расписание, дни недели, число раз); архив, секция «Archived» с восстановлением и удалением; перемещение ↑/↓ с сохранением `sort_order` |
| Бросаю | карточки с живым таймером (`дни ЧЧ:ММ:СС`), лучший результат и число попыток; Relapsed с подтверждением, правка, удаление |
| Статистика | выбор привычки (архивные помечены), периода, карточки «текущая серия / лучшая / процент», heatmap 12 недель; «Clear statistics» (удалить отметки, оставив привычку) и «Delete habit» для архивной |
| Настройки | путь к данным, версия, переключатели темы и анимаций (сохраняются в `data/ui.conf`), экспорт JSONL в домашний каталог |

Таймер обновляется раз в секунду (Rtimer). При сбросе «сорвался» текущая
попытка уходит в `best_seconds`, `attempts` увеличивается, `started_at`
становится моментом сброса.

## 6. Надёжность

- Атомарная запись, `.bak`, восстановление из `.bak`, сохранение повреждённого
  файла как `.corrupt-*`.
- Блокировка `data/locks/habits.lock` (flock): второй экземпляр показывает
  сообщение и выходит.
- Проверка размеров и UTF-8 при разборе; неизвестные типы строк игнорируются.

## 7. Сборка и тесты

```sh
./tools/get_raven.sh    # Raven в build/
make                    # build/habits
make test               # тесты ядра без GUI и X11
```

CMake-конфигурация собирает тот же бинарник (для CLion). CI запускает
`make test` на gcc и clang.

## 8. Ограничения

- Только английский интерфейс; строки — литералы в коде.
- Только X11; нативный Wayland не поддерживается.
- Raven 0.1.x: API может меняться, поэтому фиксируется конкретная версия
  в `tools/get_raven.sh` (клонируется текущий main).
